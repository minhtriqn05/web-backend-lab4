# Exercise 4 – Bug report (Task Manager API)

Found with Chrome DevTools (Console + Network) and the server terminal. All fixes are in `be/server.js` (each one is marked with `// FIX #n`).

| # | Symptom in the UI | Evidence in DevTools / terminal | Root cause | Fix |
|---|---|---|---|---|
| 1 | Page shows "Cannot reach the API", list and stats are empty | Console: `Access to fetch at 'http://localhost:5002/api/tasks' from origin 'http://127.0.0.1:5500' has been blocked by CORS policy`; Network: `OPTIONS` preflight has no `Access-Control-Allow-Origin` header | `cors({ origin: 'http://localhost:3000' })` only allows port 3000, but the UI runs on Live Server `http://127.0.0.1:5500` | Allow the UI's origin: `origin: ['http://127.0.0.1:5500', 'http://localhost:5500']` |
| 2 | Ticking, editing or deleting a task shows "Cannot reach the API" | Console: `Method PUT is not allowed by Access-Control-Allow-Methods in preflight response` (same for `DELETE`) | `methods: ['GET', 'POST']` – the preflight answer does not list PUT and DELETE | `methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS']` |
| 3 | Adding a task shows "Request failed with status 500" | Network: `POST /api/tasks` → 500, HTML error page; terminal: `TypeError: Cannot destructure property 'title' of 'req.body' as it is undefined` | `express.json()` is never registered, so the JSON body is not parsed and `req.body` is `undefined` | Add `app.use(express.json())` before the routes |
| 4 | Every task title is empty (`undefined`) | Network → `GET /api/tasks` → Preview: each item has `name` instead of `title` | `toDto()` maps `task.title` to a field called `name`, but the contract and `app.js` use `task.title` | Return `title: task.title` in `toDto()` |
| 5 | Clicking the **Done** filter never updates the list | Network: `GET /api/tasks?status=done` stays **(pending)** forever; terminal only prints `Found 1 completed task(s)` | The `status === 'done'` branch filters and logs, but never calls `res.json()`, so no response is sent | `return res.json({ success: true, data: doneTasks.map(toDto) })`; unknown status values now get a 400 |
| 6 | Stats show Active = 1 and Done = 3 although only 1 task is ticked | Network → `GET /api/tasks/stats` → Preview: `{ total: 4, active: 1, done: 3 }` | The two filters are swapped: `done` counts `!t.done` and `active` counts `t.done` | `done = tasks.filter(t => t.done)`, `active = tasks.filter(t => !t.done)` |
| 7 | Adding an empty title shows "Title is required" but a blank task still appears in the list | Network: `POST /api/tasks` → 400; the next `GET /api/tasks` contains a task with `title: ""`; terminal: `Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client` | `res.status(400).json(...)` has no `return`, so the handler keeps running, creates the task and tries to send a second response | `return res.status(400).json(...)` (and also reject a non-string title) |
| 8 | Ticking a task or editing its title shows "Task not found" | Network: `PUT /api/tasks/2` → 404 `{ success: false, message: 'Task not found' }` | `req.params.id` is the string `"2"` and `t.id` is the number `2`, so `t.id === req.params.id` is never true | Convert first: `const id = Number(req.params.id)` and compare with `id` |
| 9 | A ticked task cannot be unticked | Network: `PUT /api/tasks/2` → Payload `{ "done": false }`, Response still `"done": true` | `task.done = req.body.done || task.done` – when `done` is `false`, `\|\|` falls back to the old value `true` | Only update when a boolean is sent: `if (typeof done === 'boolean') task.done = done` (the title is checked the same way) |
| 10 | Deleting task #2 removes a different task (#3) | Network: `DELETE /api/tasks/2` → 200 `Task deleted`, but the next `GET /api/tasks` still has id 2 and id 3 is gone | `tasks.splice(id, 1)` uses the task **id** as an array **index** (id 2 is at index 1) | `const index = tasks.findIndex(t => t.id === id)` and `tasks.splice(index, 1)` |
